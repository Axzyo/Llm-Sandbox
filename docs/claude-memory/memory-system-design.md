The LLM-NPC-sandbox memory system was redesigned (2026-08-25) to these decisions:

- **Memory writing is code-only, instant, no LLM.** Perception/dialogue events become memories directly in `record_events` (sim/brain.py) at the perception tick and at `close_session`. The old LLM "tagger" is gone. Gated by `ENABLE_NPC_MEMORY` in main.py.
- **Salience was removed entirely.** It was absolute-importance (not similarity) and its 1–10 scale was a hardcoded value system. Retrieval is now similarity-only.
- **Structured memory records**, not prose: `{id, t, sense, observer_loc, direction, subject:{kind,ref,type,pos,info}}`. No `entities` list — a memory is about exactly one subject; multi-entity events are implicit (several memories). Prose is derived on demand by `render_memory` only for the LLM prompt.
- **sense = saw / heard / did** (+ `felt` fallback for unknown events). Two perceptual inputs + one action output. "said" was dropped: speaking is a `did` (an action you enacted); the listener stores the `heard`.
- **Five-axis scorer** (sim/memory.py), all deemed important, WEIGHTS STILL TBD (currently equal placeholders): time (recency) · location (`subject.pos` vs query_loc — anchored on the *thing's* position = "around here") · direction (compass `_dir_match`) · subject (token overlap on subject.type/ref/info, `_singular` stemmer so "bears"→"bear") · sense (exact match). A probe only engages the axes it specifies (time always on); denominator = sum of engaged weights so unspecified axes don't dilute.
- **Questions map onto the vocabulary**: interrogative verb → sense (seen/told/did), noun → subject, here/there → location, lately → time.
- **No embeddings — not deferred, unneeded.** An NPC's sense of danger is experiential, not ontological: a bear and a goblin are identical on first sight. Object matching is exact type-match + stemming. Genuine world-knowledge paraphrase ("furry animals"→bear) is meant to be bridged by the planned **recall action** (the LLM picks better query terms), not a vector index.
- **Dialogue = one memory per line** (heard/said), each with the spoken text in `subject.info` so content is searchable.
- **Recall model = Supplement**: passive top-k injected every LLM call, PLUS a planned `recall` action for deliberate deeper search. Passive and active recall are the same retrieval, differing only in who writes the query tokens.

Status: "Step A" implemented and tested. "Step B" (the `recall` action) is built and unit-tested — a bounded loop (MAX_RECALLS=2) in `Brain._act_with_recall`: the LLM may emit `{"action":"recall","params":{"query":...,"sense":...}}`, which retrieves and folds results into the recalled set, then re-asks. **BUT gemma4:8B does not invoke recall even when instructed to** — small-model meta-cognition is too weak. The wiring is correct and dormant; passive 5-axis recall covers the shared-token case well; the zero-lexical-overlap semantic case (question "predators" vs memory "bear") stays unbridged with this model (would need a bigger model that uses the tool, or embeddings — which were deliberately rejected). "Step C" DONE: action outcomes become `did` memories through the same `record_events` pipeline — `did_move` (arrived/unreachable, subject=destination tile) written in `step_npc`, `did_interact` (ok/out_of_range/no_los) written in `apply_intent`; dialogue-opening interacts are covered by the dialogue memory instead. "Step A" DONE: autonomy is ON (`ENABLE_NPC_THINKS = True`). The "moves for no reason" was NOT a code bug (confirmed: `move_target` is only ever set from LLM intents; the `npc.target` attention field is display-only and not even in the snapshot) — it was the model confabulating a curiosity drive to fill the survival-only vacuum. Fixed by teaching (prompt): added a required `reason` field to every action (huge for visibility — capture in `validate_intent`), legitimized idle-when-safe, and explicitly stated survival is the only concern (no explore/investigate urge). Result: clean baseline — both NPCs idle 100% when safe. Interrupt dead code REMOVED (will build fresh when a concrete need arises).

NOW ENTERING THE BEHAVIOR/TEACHING PHASE (infrastructure complete). Levers: prompts, snapshot content, eventually fine-tuning on the JSONL logs.

KEY DESIGN DECISION (2026-08-26): **the separate drives→sensation channel is rejected.** Sensation is just "recall of the present" — fear/danger/novelty must EMERGE from recalled memories, not a hardcoded string. `survival_sensation` (HP→"you feel safe/fear death") was DELETED from brain.py and both injection sites (build_snapshot, dialogue view_for); raw `hp` stays in the snapshot as a FACT, the interpretation is emergent. Consequence parked: this removes drive-weight personality → personality becomes purely experiential (you are your memories); fresh NPCs start identical, diverge through experience. Audit confirmed `survival_sensation` was the ONLY hardcoded behavioral interpretation in code (the `npc.target` attention rule is display-only, not in prompts).

THINK TRIGGER — DONE (pragmatic, 2-NPC scale): the 3-second clock was REMOVED entirely. The NPC thinks whenever a NOVEL memory forms — novelty = the new memory scores below `NOVELTY_THRESHOLD` (0.5) against the store, via the same similarity scorer used for recall (checked in `Brain._is_novel` BEFORE the memory is added). A novel memory sets `Brain.pending_think`; the main think loop consumes it (replaced the `next_think_at` clock gate). Redundant memories (a thing you already knew) don't re-trigger. Result: think on meaningful change, rest otherwise — static+safe world = silent. Key reframing that settled it: the trigger is PURE COST OPTIMIZATION (when to wake the LLM), NOT threat assessment — "dangerous bear vs harmless Dave" is the LLM's REACTION (⑤), and it EMERGES from recalled experience (no bear-harm memory → bear and Dave ARE the same, correctly), never a mechanism. Minor wart: `_is_novel` calls `retrieve`, which bumps last_accessed/access_count (novelty probes count as light rehearsal). `think_interval`/`next_think_at` fields on Entity are now unused.

ACTION VOCABULARY (2026-08-26): WORLD verbs — `move`, `interact`, `say`, `use`; COGNITION — `recall` (loops, not a world action); NULL — `none` (replaces `idle`; must stay, or forced-action confabulation returns). SELF-MANAGEMENT category (structured 2026-08-26, NOT built — redesigns the current dormant `use`): a third bucket beside WORLD and COGNITION. Triad by where the effect lands — COGNITION reads self (recall=memory, inventory-search=items), SELF-MANAGEMENT writes your own inventory/body (use · drop · equip/hold · stow/rearrange), WORLD writes outside. RULE for the self↔world boundary: "once it's yours, it's self-management; acquiring it from the world is `interact`." So drop/use/equip/stow = self-management (full authority over your own stuff; drop's item lands on a tile as a sim side-effect, but the ACT is inventory mgmt); PICK UP = `interact` (reach into the world, goes through range/LOS). So `interact` gains a second job: engage-external AND take-a-world-item. IMPLEMENTED (2026-08-26) as a GROUPED verb (chosen over separate verbs): `{"action":"inventory","params":{"op":"use|drop|equip|stow","item":"<item>"}}` replaced the old top-level `use`. Validated in `_validate_action`; executed in `enact_instant` (main.py) as an instant op; writes a `did_inventory` memory (kind "item", info carries the op) that render_memory renders op-aware ("I equipped/dropped/stowed/used …"). STILL DORMANT — no item/inventory mechanic yet, so every op fails `no_such_item` on the empty inventory; the op's real effect (consume/drop-to-world/equip) is a TODO in enact_instant. `interact` is the pick-up path (schema unchanged; needs item entities in the world, which also don't exist yet). Action list is now: WORLD — move, interact, say, inventory · COGNITION (thinking-layer, NOT world goals) — recall, wait. The old NULL `none` was REPLACED by `wait` and moved into cognition (2026-08-26): `wait` = "do nothing this turn, observe." Like `recall`, it is dropped by `goal_from_intent`/`validate_goals` (never becomes a goal), so choosing it adds no goal and the NPC simply rests; decide()'s fallbacks return `{"action":"wait"}`. Verified: safe NPCs choose `wait`, 0 goals added.

SPEECH IS A BROADCAST — the whole dialogue-session subsystem was DELETED (DialogueSession, sessions, open/close_session, enqueue_reply, respond(), the "reply" job, handle_reply, end_dialogue, send_line, dialogue-mode UI, sim/dialogue.py). Now `say` is a normal world action in the think loop: `broadcast()` in main.py writes a `did_say` to the speaker and a `heard_say` to every entity within its own `hearing_radius` (new Entity attr, default 12, IGNORES walls — sound isn't LOS). A novel `heard` memory triggers the listener's think; it decides if it was addressed and whether to reply — conversation EMERGES, no turn-taking code. Addressing is freeform (text carries "hey npc_2"). Player speech: ENTER opens a compose input (movement locks), ENTER broadcasts, ESC cancels; speech in the player's earshot shows in a HUD hear-log. Memory event kinds `did_say`/`heard_say` replace `dialogue_had`. Streaming RE-ADDED (display-only): the think call streams via `Brain._chat_streamed`/`decide(on_delta=...)`; the worker feeds deltas to a lock-guarded `live_text[eid]` buffer; the HUD types out a `say` with a █ cursor but ONLY for speakers within the player's hearing_radius. Crucially the BROADCAST (heard-memory propagation) still fires only on COMPLETION in apply_intent — you never "hear" half a sentence. Non-say actions produce no visible deltas. Chatter/ping-pong control: NONE in code — deferred to training runs (user's call). Verified: both broadcast directions (player→npc, npc→npc) pass autotests; safe survival-only NPCs correctly stay silent (no reason to speak).

REMAINING = pure ⑤ (decision QUALITY / teaching): NPCs still confabulate "move closer to investigate" despite prompt rules. Levers: prompt engineering (near-term), fine-tuning on JSONL logs (endgame). See [[llm-latency-fix]].
UPDATE 2026-08-30: added sense `felt` (interoception; `did` = external, `felt` = internal). Engine perception pass emits felt_stat when a stat's ROUNDED value changes (sim/engine.py::FELT_STATS: health/hunger/thirst). Direction in subject.type, {stat,value} in subject.info -> one-rule consolidator folds same-direction runs (full episode drain: 300 ticks -> 3 records, 'I felt my thirst fell from 99 to 0'), reversals/other stats start new records. DEFAULT_GAP_S 2s->3s (hunger cadence was exactly on the old boundary). recall accepts sense 'felt'.
