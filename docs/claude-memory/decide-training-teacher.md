- **Training approach DECIDED (2026-08-27): reward-based expert iteration, NOT plain SFT distillation.** Reward = drive-weighted sum of per-drive OUTCOME signals: `reward = Σ drives[d]·signal_d`. survival=min(hp,hunger,thirst); curiosity=novelty gained; power later. Same `Entity.drives` weights are BOTH policy input (in snapshot) AND reward weights → ONE **drive-conditioned** policy `π(goal-set|state,drives)`, trained on a SPREAD of drive profiles (never per-NPC models). NO judge LLM — world computes reward objectively. Method = expert iteration (rollout → keep high-return trajectories, normalized per drive profile → SFT on winners → repeat), round 0 policy = gemma4; escalate to PPO only if plateaus. New content (tiles/items) needs NO retraining (learned at runtime via memory + generic reward signals); only new MECHANICS/drives (e.g. power) need training.

Findings (2026-08-26):
- The old `train/extract_dataset.py` corpus (1718 rows from `runs/*.jsonl`) is unusable for the *current* game: 96% use an OLD system-prompt schema (`idle`, 3 actions, no `say`/`recall`/`reason`) and 97% are `move`. Only ~21 rows match today's 6-action schema.
- Built `train/gen_scenarios.py` + `train/teachers.py`: synthesize balanced *situations* (safe/idle, distant agent, approaching threat, low-HP, adjacency, memory-relevant) and run each through the REAL `Brain.decide()` against a pluggable teacher → logs a normal `runs/synth_*.jsonl` that `extract_dataset.py` turns into `train/data/sft.jsonl`. Guarantees schema-current, validator-gated pairs.
- gemma4 chose `none` for 40/40 situations. **But so did claude-sonnet-5: 39/40 `none`, 1 `move`** (2026-08-26, with the API key). So it is NOT a teacher-quality problem — it is a **world-model problem**.
- **Root cause (the real finding):** under the current snapshot schema + survival-only drive, `none` is the *rational* answer almost always. The state carries no survival-actionable signal — no damage source, no hunger indicator, no food, no hostile marker; HP is just a number with no shown cause. A perfect teacher correctly idles. Distilling ANY teacher here yields an always-`none` student, and that student would even be *faithful* to what the live game feeds.
- **The one thing that produced action:** the single Sonnet `move` fired off a *seeded memory* ("it's not safe near the wall") in the `memory_relevant` family — Sonnet recalled it and moved away. So the teacher acts purposefully when (and only when) the state/memory contains a survival signal.
- **Conclusion: training the DECIDE section is premature until the world has survival stakes** (damage sources, hunger→HP with a hunger sensation, food/objects) — the DESIGN.md roadmap's actual next step. Then decisions become non-trivial and worth distilling. Until then a "trained" DECIDE model is trivially always-`none`.
- Cost so far: ~$0.15 of diagnostic Sonnet calls. Did NOT run the 800-scenario set (would be ~100% `none`). Recommended teacher WHEN ready: **claude-sonnet-5** (rational, acts on real signal); ~$1.30 per 400 scenarios.
- SDK note: anthropic 1.1.0 installed; Sonnet 5 rejects `temperature` (removed on 4.6+ family) — `teachers.py` no longer sends it. `gen_scenarios.py` had a div-by-zero on the first tick (fixed with `max(elapsed,1e-9)`).
- `use` is un-promptable under the current schema: `build_snapshot()` exposes no inventory, so the agent never sees what it carries. Don't fake one in.
