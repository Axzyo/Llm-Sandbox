Built 2026-08-29 from `train/REWARD_TRAINING_SPEC.md` (branch ci/setup-pipeline):

- **A `sim/reward.py`**: `REWARD_COMPONENTS` registry `(npc, world)->float`; `reward()` = Σ drives[d]·signal. survival = min(hp,hunger,thirst)/100 (0 when dead); curiosity = types newly familiar this step — the runner measures the delta with `note_novelty(npc, brain, seen)` which stashes `npc.novelty_gained`. `DISCOUNT_PER_S = 1.0` (undiscounted). Power seam commented out.
- **B `sim/engine.py`**: all per-tick logic moved out of main.py (build_snapshot, broadcast, enact_instant, progress_move, advance_goals, reap_dead, death_cause) + `Engine` class. Sync think by default (headless, reproducible); main.py passes `dispatch_think` → its worker thread and feeds results back via `engine.post_goals()`. `ENABLE_NPC_*` flags + `PERCEPTION_INTERVAL` now live here. `sim/config.py` = shared load_config (main + runner, no pygame import in headless).
- **Think cadence restored**: `Entity.think_interval` (3.0s) — engine thinks on novelty OR cadence. Without it NPCs idled to death after the spawn novelty burst (first baseline attempt: all died at t=225 with identical returns, zero actions).
- **C `train/run_episodes.py`**: headless rollouts; drive sampler grid survival∈{0.5,1} × curiosity∈{0,0.5,1} (`profile_key` rounds to 0.25 for bucketing); writes per-episode journals + `scores.jsonl` (return/survival_s/novelty/cause per NPC) and prints per-profile aggregates (`--summarize` re-prints). `--provider transformers --adapter` for trained students.
- **D**: `extract_dataset.py --scores --top q` keeps top-quantile NPCs PER drive-profile bucket (`load_keep_set`), skips scores.jsonl in the glob.
- **E**: `sim/provider.py` `TransformersProvider` (lazy torch imports, `model` attr = name string, 4-bit w/ bnb else fp16). `train/train_lora.py`: TRL **1.12** API — prompt/completion columns + `SFTConfig(completion_only_loss=True, max_length=...)` (old DataCollatorForCompletionOnlyLM is gone). `train/requirements-train.txt`.
- **F `train/expert_iter.py`**: subprocess loop rollout→filter→train under `train/rounds/round_N/`; round-1 rollout with gemma4 IS the baseline (G); aggregates append to `train/rounds/summary.jsonl`.
- Coverage in smoke_test.py: test_reward, test_engine_headless (sync think + cadence + death), test_episode_runner (micro-episode with FakeProvider + per-profile filter).

Gotchas: pip `--upgrade` won't swap cpu→cu torch (same version number) — need `--force-reinstall --index-url .../cu128`; bnb 0.50 installs fine on Windows now. gemma4 rollout ≈ real goal-sets (9/11 thinks valid in sanity run).

3 ROUNDS RAN (2026-08-30, expert_iter --start-round 2 --init-model student-r1 --rounds 3, served via Ollama, fast): NO improvement — mean return baseline 52.9 -> r2 47.5 -> r3 49.7 -> r4 45.5; survivors 3 -> 1 -> 1 -> 0/24. Expert iteration FAILED/plateaued here. Two root causes (verified from scores): (1) ~0-12% survival -> the top-half "winners" are still dying NPCs, so the student clones dying behavior and drifts down. (2) return DOESN'T separate winners from losers — in a survival=1 bucket all 3 NPCs died at t=225 with return 62.4-62.5 (identical); return ~= drive_weight x full-meters-early, so a death at 225 scores ~ a survivor. Filtering is near-random. NOT a case for water-specific reward (owner vetoed shaping). It's that expert-iteration needs a base that sometimes succeeds. Spec's escalation trigger hit. Next options (both keep outcome-only reward): PPO (RL learns by exploration from sparse reward, no need for pre-existing good trajectories) OR seed round-0 with a stronger teacher (Claude API acts on survival signal per [[decide-training-teacher]]) then distill. Added expert_iter `--start-round`/`--init-model` resume flags. Ollama models student-r1..r4 exist.

SONNET-5 TEACHER (2026-08-30, ~$4-5): tried claude-sonnet-5 as a round-0 teacher (AnthropicProvider, `run_episodes --provider anthropic`; key set User-scope, inject via PowerShell `[Environment]::GetEnvironmentVariable(...,"User")` since harness predates setx). Result WORSE than gemma4: 0/24 survived, 0 drink events (gemma4: 3/24, 18 drinks). ROOT CAUSE (the real finding, a WORLD-design bottleneck not a policy one): 15/24 Sonnet NPCs SAW water but NONE interacted with it — because the causal-learning design (CLAUDE.md: "NPC's only source of what things do is outcome memories, not names") means a fresh NPC has NO memory that water->thirst, so nothing makes water worth trying. Instead agents fixated on berry bushes (a KNOWN reward once harvested) and hammered even EMPTY bushes 18-31x ("nothing to pick") while dying of thirst. So a smarter model EXPLOITS the known local optimum harder and explores unknowns LESS. Surviving requires blindly trying an unknown water tile to discover its effect before t~225; nothing pushes agents to try unknowns under unmet need (curiosity drive doesn't cover survival-only agents, and didn't trigger water-trying even when weighted). A teacher can't teach a bootstrap behavior it doesn't itself exhibit. This IS the user's "must problem-solve for itself" gap — but closing it is a DESIGN decision (seed a starting water memory / strengthen exploration-under-need / longer episodes), not a training run. Single-call test was misleading: it succeeded only because I handed it a water memory. AnthropicProvider committed (works, cache-marks system prompt, no temperature).
